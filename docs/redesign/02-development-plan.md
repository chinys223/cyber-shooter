# 開發落地計畫

本文件是實作規格與拆解，尚未變更遊戲程式。相依套件版本以目前 `package.json` 為準；不以升級套件作為本次重設計的前置條件。

主題限制：保留原作的科幻、霓虹、星空與雷射辨識元素。新的固定鏡頭救援玩法必須呈現雷射泡泡棒發射、太空角色及帶發光邊條的浮島；不可在落地時變成沒有科幻元素的一般田園點擊遊戲。

## 1. 先做哪一段

先交付「開始 → 六顆泡泡救援 → 啵啵反應 → 放置小風車 → 再玩／結束」的完整垂直切片，再進行兒童試玩。切片也要有暫停、重新開始和靜音，才能觀察完整體驗。

第一階段使用幾何角色、簡單地形與程式動畫。角色反應與操作回饋必須完成，背景細節可延後；一個漂亮但操作未完成的場景無法驗證核心樂趣。

### 原始碼中的待處理點

- 桌機與手機各自建立射線並遍歷場景，命中流程重複；新版統一到 `interactTarget(id)`。
- 現有射線會繼續尋找目標，未看到在一般遮蔽物處停止的規則；有機關後需明確定義遮擋。
- 現有勝利只隱藏部分 UI，仍掛載 Player 和射擊監聽；新版所有輸入需受遊戲狀態保護。
- 目前透過觸控能力判斷手機；新版同時接受滑鼠與觸控，避免混合設備被鎖定單一操作方式。
- 目前 BGM 在模組層建立，播放嘗試後即設定已開始旗標；新版僅在播放成功後更新狀態，失敗可於下次手勢重試。
- `Player.jsx` 後座力使用逐幀 state 更新；新版純視覺動畫優先留在 ref／動畫層，避免每幀更新全域 UI。
- `Level.jsx` 旋轉按幀累加，非依時間差；新版動畫需以 delta 或當局時間推進，暫停後不能因全域時鐘繼續而跳動。

以上是程式閱讀的改造依據，未聲稱已重現所有問題。

## 3. 建議模組邊界

```text
src/

  game/

    LaserBubbleWand.jsx

  ui/

  state/
    gameStore.js
    saveGame.js
  audio/

```

檔名為建議結構，不是預先建立空殼的要求。關卡內容與解鎖規則放資料層，場景元件只負責呈現與回報互動，避免第二關再複製一整個 App。

### 流程狀態

`loading → home → levelSelect → playing → result → island`

`playing ↔ paused`；`paused → levelSelect / island`；任意可恢復的載入錯誤 → `error → retry`。

| 狀態 | 可接受輸入 | 時間與資料行為 |
| --- | --- | --- |
| loading / error | 重試或載入完成 | 不啟動關卡計時 |
| home / levelSelect | 選單 | 不接收救援事件 |
| playing | 場景救援、暫停 | 推進當局時間和目標狀態 |
| paused | 選單 | 凍結動態；清空未處理輸入 |
| result | 下一關、重玩、小島 | 固定結算一次、儲存一次 |
| island | 裝飾、角色互動、選關 | 修改布置後保存 |

每顆泡泡另有 `idle → reacting → rescued`。在 `reacting` 起即禁止重複命中；成功轉移後才更新進度。連鎖也使用相同入口與去重，不直接重複加分。

### 狀態資料

| 類別 | 建議欄位 | 保存 |
| --- | --- | --- |
| 畫面流程 | `screen`, `returnScreen`, `error` | 否 |
| 當局 | `runId`, `levelId`, `waveIndex`, `rescuedIds`, `activeTime`, `challengeProgress` | 否 |
| 輔助 | `consecutiveMisses`, `idleDuration`, `assistanceLevel` | 否 |
| 收藏 | `completedLevels`, `creatureIds`, `decorationIds`, `badgeIds` | 是 |
| 小島 | `slots`, `selectedCompanionId` | 是 |
| 設定 | `musicVolume`, `sfxVolume`, `reducedMotion` | 是 |
| 存檔中介 | `schemaVersion` | 是 |

存檔使用專屬 localStorage key，例如 `bubble-rescue.save.v1`；只保存本機進度，不新增後端。載入時驗證版本與 ID；資料損毀時使用安全預設並提示，未知版本不直接覆寫。瀏覽器禁止保存時仍能遊玩，顯示「這次進度暫時無法保存」。

首次完成獎勵採集合合併，重複完成不重複發送；通關與收藏一次寫入同一份存檔，避免出現關卡解鎖但獎勵遺失。小島只允許已擁有物件放入合法格位。

```js

  waves: [
    { targetCount: 1, motion: 'still', mechanic: 'tap' },

    { targetCount: 2, motion: 'slowFloat', mechanic: 'chainIntro' }
```

連鎖關係以目標 ID 明確配置；不可把粒子效果也當作必救目標。重新開始重建當局 ID、目標與機關狀態，保留永久收藏。

## 4. 階段交付與退出條件

以下為一名熟悉此專案的前端／3D 開發者、使用簡單程式美術的初估，不是承諾工期。實際工作量由原型品質、素材要求與試玩調整決定；兒童招募等待時間另計。

| 階段 | 估計工作日 | 交付 | 才可進下一階段的條件 |
| --- | --- | --- | --- |
| P0 核心切片 | 3–5 | 首關、啵啵反應、固定鏡頭、基本流程、小風車擺放 | 三種輸入可完成流程、重玩不壞、開始首次試玩 |
| P1 依試玩修正 | 2–4 | 修正看不懂、點不到、回饋無趣等主要問題 | 至少完成一輪修改後複測，核心指標達標或有明確可行修正 |
| P2 三關首版 | 5–8 | 風車、連鎖、三角色、六裝飾、收藏及存檔 | 完整通關、重開保留、獎勵無重複、內容符合企劃 |
| P3 品質整理 | 2–4 | 實機布局、效能、載入失敗與中斷處理 | 裝置驗收通過、已知阻斷問題清零 |

初估合計 12–21 個工作日，另加招募及回饋等待；若需要正式角色建模、錄音或外包美術，另行估時。

### P0 可直接拆成的工作項目

1. 抽出遊戲流程狀態，建好開始、暫停、結算、重玩。
2. 將主模式換為固定鏡頭，統一點擊入口和 UI 事件隔離。
3. 建立六顆泡泡與三波配置，支援目標狀態去重。
4. 做啵啵的待機、受救援、噴嚏三種動作、雷射泡泡棒短光束與簡短音效。
5. 加入誤觸／停滯輔助，完成無文字也可理解的教學。
6. 做一個島格、一件風車與放置回饋，保存首關成果。
7. 以真實手機、平板或桌機完成初測，執行第一輪兒童試玩。

## 6. 效能與技術驗收

以下是開發目標，尚未實測。先記錄實際測試裝置、作業系統、瀏覽器與視窗尺寸，再判斷是否達標。

- 測試矩陣至少包含一台 Android 手機、一台 iPad／iPhone 和一台桌機；混合觸控筆電若為實際使用設備，也列入。
- 一般操作以 60 FPS 為理想；指定低階測試機的 60 秒遊戲取樣中，至少 95% 幀不超過 33.3ms。若未達標，先減少陰影、粒子與解析度。
- 同屏可互動目標上限先設 5；先以簡單材質與有限粒子驗證，不直接沿用原本 5,000 星點與兩組共 1,300 粒子設定。
- 冷啟動至可互動以 5 秒內為初始目標，在固定約 10Mbps 下載與 100ms 延遲條件量測；下載中有進度／狀態，失敗可重試。
- 互動後 100ms 內開始視覺回應；長音效或動畫不阻塞下一個合法目標。
- 瀏覽器分頁切走、螢幕旋轉、音訊暫停、連續重玩 10 次均不產生卡住輸入或重複事件。
- WebGL 不可用或場景載入失敗，顯示能理解的提示與重試，不停在全黑畫面。

### 必測行為

| 測試 | 預期 |
| --- | --- |
| 快速連點同一顆泡泡 | 救援只計一次，音效與獎勵不重複 |
| 暫停期間點場景 | 不救援、不推進機關、不偷偷通關 |
| 結算後繼續點原目標位置 | 不再改動當局進度 |
| 重玩與回小島 | 當局重置，永久收藏保留 |
| 風車關閉／開啟 | 依可見開口正確判定；輔助延長可用時間 |
| 連鎖與手動點擊同時發生 | 去重，最終進度與目標總數一致 |
| 首次／再次通關 | 固定獎勵僅領一次，已獲徽章保留 |
| 存檔損毀或無法寫入 | 遊戲可繼續，提示狀態，不整頁崩潰 |
| 手指取消／滑出區域／點選單 | 無誤射、無連續輸入殘留 |
| 靜音／柔和模式／鍵盤 | 各自仍能獨立完成三關 |

實作完成後執行專案既有 `npm run lint` 與 `npm run build`。自動化優先覆蓋去重、關卡狀態、獎勵冪等、存檔恢復等有狀態邏輯；動畫品質、可點性與好玩程度需實機與真人驗證。

## 7. 風險與取捨

| 風險 | 最早驗證方式 | 處理 |
| --- | --- | --- |
| 點泡泡很快無聊 | P0 觀察孩子是否只是在清數量 | 增加選順序和可預期的連鎖，避免單純增加目標數 |
| 角色只有可愛外形，沒有記憶點 | 試玩後讓孩子描述最喜歡的片段 | 優先修改動作與性格，不急著增加第四隻 |
| 低齡孩子仍點不到 | 記錄誤觸和停滯位置 | 調整目標尺寸、速度、間距與輔助 |
| 收藏比關卡有趣 | 分開詢問想玩救援或布置 | 若多輪結果一致，可把關卡縮短並重配開發投入 |
| 小島範圍膨脹 | 固定六格、六裝飾的首版清單 | 延後自由建造與複雜物理 |
| 手機效能不足 | P0 就上目標裝置測試 | 先減特效，再擴關卡；不等美術完成才測 |
