# 兒童試玩與驗證計畫

## 1. 要回答的問題

「看起來可愛」不是通過條件。要確認孩子是否能自行開始、理解操作、享受回饋，並在可自由結束時仍選擇再次遊玩。

另記錄孩子如何描述世界與工具，確認仍能辨認太空、雷射或未來樂園主題；不先用提問暗示答案。對玩過舊版的孩子，可另問「哪些地方讓你想到原本的遊戲？」這組不混入首次上手數據。

本計畫為小規模形成性測試，結果用於找問題和修設計，不能當作所有兒童偏好的統計證明。

## 2. 招募與分組

第一輪建議 6 名兒童：6–7 歲與 8–9 歲各 3 名，盡量涵蓋不同遊戲熟悉程度。至少一半使用平常會玩的觸控設備。記錄年齡區間、裝置和操作經驗即可，不需在遊戲中建立帳號。

由照顧者同意並陪同，孩子可隨時結束。若要錄影另取得同意；未錄影也可用匿名代號和觀察筆記完成測試。測試者避免教導答案或以稱讚催促孩子繼續。

第二輪找 6 名未玩過新版的孩子複測上手問題；如邀原參與者回來，另記錄為熟悉玩家，不混入首次上手數據。

## 3. 每位約 10–15 分鐘流程

| 時段 | 操作 | 主持人說法與觀察 |
| --- | --- | --- |
| 0–1 分鐘 | 介紹可以隨時停止 | 「這是一個還在做的遊戲，想試試看嗎？不想玩也可以。」 |
| 1–4 分鐘 | 從首頁玩首關 | 「你可以自己試試看。」先觀察，不先教點哪裡 |
| 4–6 分鐘 | 看結算與小島 | 觀察是否知道獎勵是什麼、會不會擺風車 |
| 6–9 分鐘 | 自由選下一步 | 「你想再玩、玩小島，還是先結束？」語氣與選項平衡 |
| 9–12 分鐘 | 短訪談 | 問喜歡與不喜歡的具體片段 |
| 最後 | 感謝與結束 | 不以完成關卡或多玩一次作為獲得感謝的條件 |

若卡住 20 秒或主動求助，可給第一級提示「看看哪裡在動」；仍無法繼續才示範一次。記錄提示時間與級別，該段不能記成獨立完成。孩子出現明顯不適或不願繼續就結束，不為補足數據延長。

P0 只有首關時，自由選擇提供「重玩首關／玩小島／結束」；P2 才測下一關選擇。不要用尚未開發的內容當作已可玩的承諾。

## 4. 核心指標與初始門檻

以下門檻為本案產品決策值，並非研究得到的通用標準。6 人樣本請報人數及各人結果，不只報百分比。

| 指標 | 定義 | 6 人試玩初始目標 |
| --- | --- | --- |
| 首次成功 | 首顆泡泡可互動起，到第一次正確救援 | 至少 5 人在 15 秒內、不靠成人提示成功 |
| 理解任務 | 完成首波後能用動作或自己的話表現「救出泡泡中的角色」 | 至少 5 人理解，不要求會念文字 |
| 獨立完成 | 從開始首關到結算，全程沒有成人操作或具體指示 | 至少 5 人完成；另記是否用了遊戲內輔助 |
| 明確喜好 | 自由敘述喜歡的動作、角色或機關，或主動再觸發它 | 至少 4 人有具體片段；不把微笑當唯一證據 |
| 自主繼續 | 中性提供三個選項後，自己選擇重玩或下一關並實際開始 | 至少 4 人；「只想布置小島」另記，不混算 |
| 收藏理解 | 能指出剛得到的裝飾並放置一次 | 至少 5 人完成 |
| 嚴重阻礙 | 畫面卡住、主要目標點不到、無法回選單或明顯不適 | 0 件未解決問題 |

以首次成功、獨立完成和嚴重阻礙作為擴充內容前的必要關卡。喜好與自主繼續未達標時，先改善回饋或玩法，再複測，不直接追加內容。

不以遊玩時間越長越好作為目標；能在完整結束點滿意停下也是正向結果。

## 5. 觀察紀錄表

每位複製一份：

```text
玩家代號：
年齡區間：6–7／8–9／其他
裝置／瀏覽器／直橫向：
平常遊戲經驗：少／偶爾／常玩
版本／關卡：

首次可互動時間：
第一次成功時間：
是否成人提示／級別：
首關完成：是／否
遊戲內輔助觸發：次數、觸發原因
卡住或誤觸：畫面位置、當時在做什麼
最喜歡的片段：孩子原話或動作
不喜歡的片段：孩子原話或動作
小島放置：獨立／提示後／未完成
自由選擇：重玩／下一關／小島／結束
選擇後是否真的開始操作：
中途停止原因：
本次最重要的一個問題：
下一版要調整的一個假設：
```

避免「你是不是很喜歡這隻？」這類引導句。改問：「剛剛哪一段你還記得？」「哪裡讓你不知道怎麼做？」「如果可以改一件事，你想改什麼？」不喜歡也能直接說。

## 6. 可選的開發觀測事件

P0 可完全由人工記錄；需要更精確時間時再加入僅供開發測試的本機事件記錄。首版不因此新增外部分析服務。

| 事件 | 用途 | 最少欄位 |
| --- | --- | --- |
| `session_started` | 識別本次匿名測試 | 暫時 sessionId、buildId |
| `level_started` | 計算首次成功與完成時間 | levelId、相對時間 |
| `target_rescued` | 操作成功與去重驗證 | targetId、wave、相對時間 |
| `tap_missed` | 誤觸位置類型 | 空白／機關／已完成目標，不記個人資料 |
| `assist_shown` | 輔助是否過多 | 原因、級別 |
| `level_completed` | 完成與挑戰 | activeDuration、assistCount |
| `next_action_selected` | 中性選擇後行為 | replay／next／island／exit |
| `decoration_placed` | 收藏是否能被使用 | decorationId、slotId |

相對時間使用單調時間來源；關卡有效時間扣除暫停。事件需帶當局 ID，防止重玩資料混在一起。退出網頁不一定有可靠事件，離開原因以人工觀察補足，不把缺少事件直接當作不喜歡。

## 7. 根據結果修改

| 觀察結果 | 優先解釋假設 | 下一版變更 |
| --- | --- | --- |
| 看見泡泡卻沒點 | 可互動提示不清楚 | 調整手指示範、輪廓與位置 |
| 一直點卻不中 | 命中區或事件處理有問題 | 先修點選，再調整速度，檢查 UI 遮擋 |
| 能完成但不想再玩 | 行動結果或決策太單調 | 對比角色回應與連鎖順序，不先擴關卡數 |
| 一直看動畫而操作停住 | 演出太長或結束訊號不清楚 | 縮短演出、明確顯示下個目標 |
| 只想玩小島 | 布置可能比救援更吸引人 | 下一輪提供更短救援與更多角色互動作比較 |
| 6–7 歲卡住、8–9 歲通過 | 難度與提示不適合較年幼組 | 調整預設輔助，分年齡呈現結果 |
| 熟練孩子嫌簡單 | 缺少可選擇的技巧表現 | 增加自選挑戰，不提高所有人的基礎門檻 |

一次改一個主要假設，保留版本編號和調整記錄。若比較兩種玩法，使用相同內容量、相近演出品質，並輪換先後順序，避免新鮮感與練習效果被當作偏好。

## 8. 完成報告格式

測試完成後產出一頁摘要：版本、參與人數與年齡分布、每項指標達成人數、三個主要問題、孩子原話、下一輪只改哪些內容，以及「擴充／修正後複測／暫停此方向」的決策。

只有當孩子實際使用的證據支持設計，才宣稱新版更適合這批受測玩家。未完成測試前，對外描述為「以兒童易上手與角色互動為目標的設計提案」。
